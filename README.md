# Car-GraphRAG

Car-GraphRAG 是一个面向汽车工业领域的知识图谱与智能问答项目。

本项目通过构建汽车工业知识图谱，并结合 GraphRAG（Graph Retrieval-Augmented Generation，图检索增强生成）实现领域专家问答，为大语言模型的分析与决策提供知识支撑，最终服务于汽车生产线的智能化与自动化。

## 项目目标

- 整理和扩展汽车工业领域知识文档；
- 构建汽车工业知识图谱；
- 使用 GraphRAG 对知识图谱进行索引和检索；
- 实现面向汽车工业场景的专家问答；
- 为大语言模型在汽车产线中的决策提供支持；
- 探索知识图谱与大语言模型在汽车产线自动化中的应用。


## 知识文档

汽车工业领域的知识文档通常包含企业内部资料、生产规范、工艺流程和设备说明等内容，公开资料相对有限，收集难度较大。

因此，本项目在已有汽车工业资料的基础上，使用 AI 对相关知识进行补充和扩展。

具体内容请参考：

```text
汽车工业产线知识文档.txt
```


## 知识图谱构建

本项目主要采用 GraphRAG 中的 BYOG（Bring Your Own Graph，自带知识图谱）方案。

与完全依赖 GraphRAG 自动抽取知识图谱的方式不同，本项目首先根据汽车工业领域知识手动构建知识图谱，再将图数据导入 GraphRAG，用于后续的索引、检索和问答。

## 本地部署

### 1. 环境准备

在开始部署前，请确保本地已经安装并配置以下环境：

- Python；
- GraphRAG；
- Neo4j；
- One API；
- 可调用的大语言模型 API；
- 可调用的 Embedding 模型 API。

建议使用虚拟环境管理项目依赖。

例如：

```bash
conda create -n car-graphrag python=3.10 -y
conda activate car-graphrag
```

随后根据项目依赖安装所需的软件包。

### 2. 搭建 One API

首先配置大语言模型和 Embedding 模型所需的 API Key。

完成模型渠道配置后，启动 One API 服务，并开放对应的本地访问端口。

GraphRAG 后续将通过该接口调用：

- 大语言模型；
- Embedding 模型；
- 其他兼容 OpenAI API 格式的模型服务。

请根据实际部署环境，在 GraphRAG 配置文件中填写：

- API 地址；
- API Key；
- 模型名称；
- Embedding 模型名称。

> 请勿将真实 API Key 直接上传至 GitHub。建议通过环境变量或本地 `.env` 文件进行管理，并将 `.env` 添加到 `.gitignore`。

### 4. 导出知识图谱

完成 Neo4j 知识图谱构建后，需要将图数据导出为 `.parquet` 格式文件。

这些文件将供 GraphRAG：

- 还原知识图谱结构；
- 读取实体与关系；
- 建立文本单元与图节点之间的联系；
- 执行后续的社区划分和检索。

导出前请确保 Neo4j 的连接信息配置正确。

### 5. 构建 GraphRAG 索引

进入 GraphRAG 项目根目录后，执行：

```bash
python -m graphrag.index --root .
```

执行索引构建后，GraphRAG 将对项目数据进行处理，主要包括：

- 读取知识文档与图数据；
- 生成文本单元 `text_unit`；
- 对文本单元进行 Embedding；
- 处理实体和关系；
- 对知识图谱进行社区划分；
- 生成社区摘要；
- 创建后续检索所需的索引文件。

索引构建时间取决于以下因素：

- 知识文档数量；
- 图谱规模；
- Embedding 模型调用速度；
- 大语言模型调用速度；
- API 的并发限制；
- 本地计算资源。

## 知识检索

本项目采用服务器—客户端架构实现问答服务。

同时，也可以直接使用 GraphRAG 提供的命令行调试入口进行检索。

进入项目根目录后执行：

```bash
python -m graphrag.query --root .
```

GraphRAG 常用的查询方式主要包括：

### Global Search

Global Search 适合回答全局性、总结性和概括性问题。

例如：

- 汽车生产线主要包含哪些工艺环节？
- 汽车工业中的质量控制体系是如何组成的？
- 焊装、涂装和总装环节之间有什么关系？
- 汽车智能制造的主要技术方向有哪些？

Global Search 通常基于知识图谱中的社区摘要进行回答，更适合从整体角度分析问题。

### Local Search

Local Search 适合回答具体实体、局部关系和细节性问题。

例如：

- 某类焊接机器人主要用于哪个生产环节？
- PLC 与工业机器人控制器之间如何通信？
- 涂装车间中的喷涂设备有哪些组成部分？
- 某个设备故障可能影响哪些后续工序？

Local Search 通常会结合相关实体、关系、文本单元和上下文信息进行回答，更适合查询具体知识。

## 查询方式选择

| 查询方式 | 适用场景 | 主要特点 |
| --- | --- | --- |
| Global Search | 全局总结、趋势分析、系统性问题 | 基于社区及社区摘要进行回答 |
| Local Search | 实体查询、关系查询、局部细节问题 | 基于相关实体、关系和文本上下文回答 |

在实际使用中，可以根据问题类型选择合适的检索方式：

- 需要了解整个汽车生产体系时，优先使用 Global Search；
- 需要查询设备、工艺或实体关系时，优先使用 Local Search。
